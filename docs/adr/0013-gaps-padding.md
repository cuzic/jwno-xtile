# 0013. 窓の間の隙間（gap）と画面の端の余白（padding）

- 状態: Proposed（2026-11-03。Opus レビュー待ち）
- 日付: 2026-11-03

## Context

タイルが隙間なく並ぶ（I7）のは xmonad の既定だが、窓の間と画面の端に少し余白を置く設定（xmonad の `XMonad.Layout.Spacing`、i3 の `gaps`）は広く使われる。今は設定が無い。
レイアウトの矩形計算は xmonad の `Layout.hs` と厳密に一致させている（ADR 0007）ので、それを変えずに足したい。

**Windows 特有の事実**（`docs/spike/`）: 窓の「見える枠」は DWM の拡張枠（影・透明な縁を除く）で、アダプタの `:place` は見える枠を目標の矩形に合わせる（CT-5: 実機・ホストで 0 px 差）。
したがって、Core が出す矩形が「見える枠」になり、gap はそのまま見た目の隙間になる。

## Decision

### D-1 設定
- State に `:gap`（窓の間の隙間、整数 ≥ 0）と `:padding`（画面の端の余白、整数 ≥ 0）を持つ（`st/make` の opts。既定は両方 0）。**両方 0 なら、全ての矩形が今と完全に同一**（互換のプロパティテストで担保）。
- 変更は command `[:command :set-gap n]`・`[:command :set-padding n]`（実行時に変える。既定の束縛は無し。設定ファイルから初期値を渡せる）。範囲は 0〜`min(screen.w, screen.h)/8`（それ以上は無視。極端な値で矩形が消えないため）。

### D-2 矩形の計算（レイアウトは変えない）
`placements` は、モニタごとに次のとおり計算する（`arrange` の中身は変えない）。
1. **padding**: 作業領域 `screen` を四辺で `padding` ずつ縮めた矩形 `inner` を作る。
2. `arrange layout params inner ids` を呼ぶ（xmonad と同じ結果。`inner` に対して隙間なく並ぶ）。
3. **gap**: 各矩形について、**隣のタイルと接している辺**だけを `gap/2` 縮める（`inner` の端に接する辺は縮めない。端の余白は padding が担う）。奇数の `gap` は、左／上の辺に切り上げて配る
   （隣り合う 2 枚の合計が丁寧に `gap` になる）。`Full` は全タイルが同じ矩形なので gap を適用しない（重なるため）。
- 矩形が幅または高さ 0 以下になる場合は、その辺の縮めを減らして最小 1 ピクセルを残す（I6: `pos? w h` を保つ）。

### D-3 不変条件
- **G-1** gap=0・padding=0 のとき、`placements` は今と同一（凍結した旧 Core との差分テストの対象に含める）。
- **G-2** 全ての矩形は `inner` の中にあり、`pos?`（I6 の拡張）。**G-3** gap>0 のとき、隣接するタイルの間の距離は `gap`（1 ピクセルの丸めを除く）。**G-4** I7（隙間なく覆う）は gap=0 のときだけ成り立つ。padding>0 でも、矩形の和は `inner` を覆う。
- Tall／Wide／Full の全てで、`ids` の数 0〜20 のとき、矩形は互いに重ならない（Full を除く）。

### D-4 アダプタと既知の制限
- アダプタは変更不要（Core が矩形を出す）。`opts :gap`・`:padding` を `st/make` へ渡す。
- Windows の窓には最小サイズがあり、小さい矩形を要求しても大きい枠になりうる（`:misfit` の再配置が 3 回で諦める。ADR 0005）。gap が大きいと、最小サイズの窓が隣に重なる。許容する（既存の制限）。
- フロートの窓は gap の対象外（Core が位置を持たない）。

### 採らなかった案
- **レイアウト関数の中で gap を計算する**: `arrange` の xmonad との厳密な一致（X1 の差分テスト）を壊す。後処理にすれば、gap=0 で自明に一致する。
- **アダプタで窓の枠を縮める（`:place` の直前）**: Core のモデルと実際の矩形がずれ、`:misfit`／`window-moved` の比較が常に不一致になる。Core が最終の矩形を出す。
- **gap を窓ごとに変える**: 需要が無い。
